# 코드 리뷰 기준

`ios-reviewer` 에이전트와 직접 리뷰하는 AI가 함께 따르는 기준임. 프로젝트 규칙은 [AGENTS.md](../AGENTS.md) 참고.

## 원칙

- 파일을 수정·생성하거나 커밋·푸시하지 않음. 실행하는 명령은 빌드, git·gh 조회, 검색뿐이며 시뮬레이터는 실행하지 않음.
- 변경된 코드 안에서만 리뷰함. 무관한 기존 코드와 취향은 지적하지 않음.
- 요청에 범위가 없으면 `git diff origin/main...HEAD`와 미커밋 변경(`git diff HEAD`)을 대상으로 함.

## 확인 항목

### 1. 빌드

- [AGENTS.md의 빌드 확인 명령](../AGENTS.md#ai-검증과-보고)을 한 번 실행함.
- 실패하면 오류 위치와 메시지를 High로 보고함. 이번 변경과 무관한 기존 실패면 그렇게 표시함.

### 2. PR 내용과 일치

- 현재 브랜치의 PR이 있으면 `gh pr view`로 제목·본문을, 연결된 이슈는 `gh issue view`로 확인함.
  PR이 없으면 이슈나 사용자가 설명한 작업 목적과 비교함. 비교할 대상이 없으면 확인하지 못함으로 보고함.
- PR에 적힌 작업이 빠졌는지, 적히지 않은 변경(범위 밖 수정·임시 코드)이 섞였는지 확인함.

### 3. 일반 코드 리뷰

위험이 큰 것부터 확인함.

- 크래시: 강제 언래핑, 배열 인덱스 범위, 잘못된 타입 캐스팅.
- 동시성·상태: 분리한 작업의 UI 상태 변경이 메인 액터에서 일어나는지, `@Observable` ViewModel을 `@State`로 소유하는지.
- 비동기 처리: 로딩이 성공·실패 모두에서 해제되는지, 작업 취소, 빈 catch·근거 없는 `try?`.
- 네트워크: `BaseService`·`EndPoint` 사용, 오류 구분, 하드코딩한 주소·토큰, 로그의 토큰·개인정보.
- 호환성: iOS 17보다 새로운 API를 `#available` 없이 쓰는지.
- 영향 범위: 공통 코드(`Data/Network/Base`, `Presentation/Common`) 변경은 사용처를 검색해 확인함.
  다른 사람 화면과 연결된 변경은 `docs/features/`의 해당 문서를 함께 확인함.
- 팀 규칙: AGENTS.md의 Swift 핵심 규칙, 공통 폰트·Assets 재사용, 남은 Preview·print, `docs/features/<화면>.md` 갱신.

## 보고 형식

- 맨 위에 항목별 결과를 한 줄씩 씀. 빌드(성공·실패), PR 일치(일치·불일치·확인하지 못함), 코드 리뷰 지적 개수.
- 지적마다 심각도, 위치(`파일:줄`), 문제, 근거, 수정 제안 한 줄을 씀. 지적이 없으면 "지적 없음"이라고 씀.
  - High: 빌드 실패, 크래시, 데이터 손실, 비밀값 노출.
  - Medium: 잘못된 동작, PR 내용과 다른 변경, 다른 팀원의 작업에 영향을 주는 규칙 위반.
  - Low: 동작에는 영향이 없는 정리 수준.
- 확실하지 않은 지적은 "추정"으로 표시함. 확인하지 못한 부분은 마지막에 따로 씀.
